This is a new native WebAuthn PRF path. Creation supplies PRF evaluation input, including the reviewed Windows compatibility fix. Exact-ID, platform-only, UV-required assertions compare the creation/first/repeated secret and a changed input. Existing libsodium AES-GCM checks recovery, wrong-key/associated-data refusal and ciphertext tamper rejection. Native cancellation/deadlines, session guards, bounded zeroized output and unconditional exact app test-passkey deletion apply. Failed deletion is reported and retried by the next synthetic run in the same process; crash cleanup across restarts is not implemented. The read-only action never deletes credentials. Only a new reserved-RP test passkey is used, with no real-vault credentials, OS AIK/key operations, TPM reset or security-setting changes.

API 9 is required for explicit authenticator routing, not assumed to be the first PRF implementation. Older versions install normally and return a blocked report before creation. `Windows Hello` is only a display-name routing candidate, not hardware proof. `prf-roundtrip-passed` means the synthetic PRF/AES checks and cleanup passed; it still reports `eligible/enrolled/unlocked: false`, `tpmBinding: not-verified` and all four unresolved physical gates.
