# File-safe boundaries and limits

Rust owns password derivation, independent random root, authenticated catalog and object keys. The password worker remains KDBX-only. Main-window capabilities expose typed metadata/edit/import/export/backup/recovery commands; none accepts a renderer filesystem path, decrypts arbitrary objects, launches a process or returns original document bytes. Native dialogs establish path authorization. Remote origins/other windows cannot call these commands. Export is an explicit plaintext exception. A compromised privileged host/OS or same-user malware is outside the portable at-rest protection.

Strict opaque identifiers bind the vault, key epoch, snapshot and version. Password/key/catalog bounds precede cryptography. Catalog graphs and exact integer counters are validated before constructing object paths. Header/frame associated data binds context, order and ciphertext length. Final authentication, whole size and digest are mandatory. Native session tokens are independently random and checked alongside a monotonic deadline and cancellation generation. Lock revocation does not wait for filesystem I/O; usable store buffers are dropped at the next bounded checkpoint after blocked I/O returns. UI request generations discard stale metadata. OS/power callbacks lock both services. Timeout, input quotas and bounded transfer admission limit accidental bulk-work amplification.

Windows paths reject reparse points/alternate streams/device names and pin opened ancestors. Regular files are opened with authoritative handle checks; imported/backup source handles deny concurrent writers/deletion. Managed directories and newly created outputs use a verified protected user/SYSTEM DACL. Portable Python recovery uses independent libsodium-backed primitives, strict validation and no-follow descriptor traversal/private exclusive output. These mechanics are not claims of perfect memory/SSD/OS-cache erasure or rollback-proof offline storage.

Immutable ciphertext dependencies are flushed/read back before atomically replacing HEAD; ACTIVE selects a complete local generation. Current plus five opaque prior heads are retained; inaccessible older epochs cause conservative retention. No plaintext catalog index, WAL, thumbnail cache or full-text index is written. Complete backup plans contain ciphertext handles and HEAD bytes, not live root/object keys or decrypted catalog. Failed/partial copies never report successful publication. Tracked digest/identity checks prevent pruning unrelated or changed directories.

A separate parser sandbox must be proved before adding PDF/image/text engines. No parser is currently linked into Rust or the main WebView. Preview remains unavailable. A plain subprocess, extra Tauri window, PDF.js worker or iframe would not satisfy the supplied isolation requirement. No test driver is linked into the installer; fixture writers live in Cargo examples/tests only. File-safe Hello now uses an independent opt-in PRF/TPM envelope; the random root stays native, and actual catalog authentication precedes token publication. Fresh user verification and exact local TPM-key evidence are required on create/reopen. No consent-boolean or software-key fallback is provided. See [the native boundary and evidence limits](WINDOWS_HELLO.md).

Remaining evidence gaps include physical Windows 11 standard-user/TPM/Kensington operation, actual AppContainer token/handle/network/filesystem denial, viewer UX/resource tests, exhaustive OS crash/disk-full fault injection and privacy scans of installed-profile/recent-file/temp/clipboard locations. Existing password/PWA physical-iPhone gates also remain open. See [ACCEPTANCE.md](ACCEPTANCE.md) for individual statuses rather than assuming unit tests prove OS enforcement.
