# Experimental Windows file safe

Open **File Safe** from the Windows app's module selector, even while Passwords is locked. Create an independent master password. It is not derived from or saved in the password database. Passwords and File Safe unlock independently; their local manual locks affect their own module. **Lock all**, Windows session lock/user switching and suspend revoke both sessions. File Safe defaults to a stricter two-minute inactivity deadline and offers 30 seconds, one, two and five minutes. Its interval is persisted independently. Background time counts; polling/backup work does not renew the deadline.

Import copies regular files or a folder using the native picker. Original files stay in place. Symlinks, junctions and hardlinks are refused/skipped; never recursively unpack archives. Every accepted object is encrypted and fully read back before the catalog commit is acknowledged. A same-name import creates a separate file. **Replace with a new version** explicitly appends immutable content to the selected file. Cancel stops at bounded streaming checkpoints; already committed files stay saved. Source paths are transient and do not enter the catalog.

Use the [explorer](EXPLORER.md): folders and files appear in one column list, with folder entries first. Enter a folder by its name, move up using **[..]** or the parent button, and use Back/Forward or the logical breadcrumb path. New folders and imports belong to the current folder. **File-safe settings** opens a separate screen for Hello, backups, recovery, password and inactivity; **Back to files** preserves the current folder. Lock clears the path/history and a new unlock starts at the root.

Use virtual folders, local search of names/tags/notes, name/date/size sorting, favorites and multi-selection. The native API returns at most 200 file rows; the UI pages by 100 and renders only a small visible window. Import outcomes and child folders have separate bounded pages. The details form supports rename, notes, tags, favorite and moving to a displayed folder. Version history keeps current plus ten prior versions. Making an old version current creates a new catalog snapshot. Recycle-bin files remain until explicit permanent removal; old encrypted recovery snapshots and backups may still retain their content. Retained content bytes exclude encryption overhead and conservatively retained orphan/older-generation ciphertext; this is not a physical disk-usage total.

**Export unencrypted copy** requires explicit acknowledgment and a native save destination. Existing destinations are refused. Verification completes before the final file is published. The copy remains outside the safe. There is no external-open, drag-out or content-copy command. A canceled/crashed export can leave a temporary plaintext remnant; normal error handling removes it best-effort.

In **File-safe settings**, choose an external automatic-backup folder separately from the safe/password directories. New commits replace the queued ciphertext snapshot and restart a 30-second debounce. At most one copy runs and one newest plan waits. A pinned copy can finish after lock because it has no keys. Status identifies pending/current copied snapshots; **Ciphertext copy verified** means bytes were read back, not that independent password recovery was tested. Default retention is ten tracked managed packages. Retention checks directory identity and the entire owned-file digest manifest; unrelated/manual packages and modified packages are preserved. Failure leaves local commits intact. A manual encrypted copy is never tracked for automatic pruning.

To restore, choose a complete package and fully verify it with its own password. Confirmation refers to that same opaque candidate. Enter its password again and acknowledge replacement. Rust re-verifies the complete package and stages a new local generation before atomically selecting it. Source and old encrypted generation remain unchanged; the safe returns locked. A missing/corrupt object never replaces the current generation. Local `before-restore/*.active` locators identify preserved generations for manual recovery; these are local bookkeeping, not portable packages.

Changing the password rotates root/key epoch and re-encrypts the catalog, retaining immutable object keys inside the new catalog. It does not rewrite every existing content object. Old copies and old epochs may remain readable with their old password. Future versions receive fresh random keys. Whole-directory rollback is not prevented by this offline format. Conservative retention keeps uncertain historical ciphertext; no destructive garbage collector is enabled.

Windows Hello now has an independent experimental opt-in for this safe: open **File-safe settings**, expand **Windows Hello for File Safe**, confirm its master password and connect. Session mode is default; remembered 6/12/24-hour modes are explicit. The safe root stays native, and password backup recovery remains available. See [connection, protection and remaining hardware acceptance](WINDOWS_HELLO.md).

Preview remains unavailable pending the required AppContainer/LPAC disk/network denial proof. No parser or isolation bypass is packaged. Full feature acceptance and production readiness remain subject to the open gates in [ACCEPTANCE.md](ACCEPTANCE.md).
