# File-safe portable v1 contract

The exact byte layout is frozen by [Encryption and Storage](spec/ENCRYPTION_AND_STORAGE.md). All integers are little-endian; all magic values are exactly eight bytes. Password header 140 bytes (`FVKEY001`, 92-byte AD); catalog header 88 bytes (`FVCAT001`, all header bytes as AD); object header 64 bytes (`FVOBJ001`, plus frame index and encoded frame length as frame AD). Password: unmodified UTF-8, 1–1024 bytes. Explicit Argon2id13, opslimit 3, memlimit 64 MiB by default; accepted bounds 3–10 and 64–256 MiB in whole MiB units. Root/object keys and opaque IDs are freshly random. HKDF-SHA-256 info `file-safe/catalog/v1`, raw vault ID as salt.

[Catalog JSON Schema](../../tools/vault-recovery/src/vault_recovery/file_safe/catalog-v1.schema.json) is authoritative for exact field names. It uses strict UTF-8 JSON without duplicate or unknown keys, exact unsigned integer counters, padded standard Base64 32-byte object keys, lowercase hex IDs/hashes, UTC timestamps with exactly three decimal digits. String bounds are UTF-8 bytes for names/tags/notes/media hints (schema character bounds are only the first layer). One root folder has an empty name and null parent; other folders require a nonempty name. IDs/references are unique and valid, folder graphs have no cycles and depth ≤64, at most 50,000 files/folders and 100,000 total retained versions. Exactly one current version reference per file, including trash. Names contain no NUL/control characters; recovery additionally sanitizes destination-specific unsafe names and reports the mapping.

Catalog plaintext ≤64 MiB; secretstream frames ≤1 MiB plaintext, only full nonfinal MESSAGE frames and exactly one FINAL frame. Empty final frames (including exact chunk boundaries) are accepted. Full length and SHA-256 are checked before successful verification/publication. Max file size 1 TiB; preview has smaller budgets and remains disabled without proved isolation.

Local-only `ACTIVE.json` selects `stores/<store_id>/<vault_id>` (both opaque IDs), keeping old restore generations intact; it is an untrusted strict locator, not an authentication claim. HEAD commit checks the exact previous locator and pinned directory identity. Immutable dependencies are published before HEAD. Previous locators remain encrypted and recoverable; this increment uses conservative retention rather than destructive garbage collection when older root epochs cannot be read. Backup packages contain only HEAD plus its matching key/catalog and reachable objects, never ACTIVE/locks/settings/Hello/staging. Whole-directory rollback cannot be ruled out.

Crypto provenance: libsodium-rs 0.2.5 (upstream libsodium binding), PyNaCl 1.6.2, cryptography 50.0.2 HKDF. Test vectors and cross-reading must pass before real-data use. This is an experimental application format, not an audited standard.
