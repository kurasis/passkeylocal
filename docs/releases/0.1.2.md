# PassKey Local 0.1.2

[Published release](https://github.com/kurasis/passkeylocal/releases/tag/desktop-v0.1.2). Native/document title: `PassKey Local (0.1.2)`.

- [Windows x64 0.1.2 ZIP](https://github.com/kurasis/passkeylocal/releases/download/desktop-v0.1.2/PassKey-Local-Windows-x64-0.1.2-unsigned.zip) — unsigned experimental installer with bundled official WebView2 runtime.
- [Cloudflare Pages 0.1.2 ZIP](https://github.com/kurasis/passkeylocal/releases/download/desktop-v0.1.2/passkeylocal-cloudflare-pages-0.1.2.zip) — production PWA with the optional same-origin icon endpoint, ready for manual upload.
- SHA-256 sidecars and a versioned provenance manifest accompany both archives.

Website icons are off by default. Website wins over Title; only a bare-domain Title is eligible when Website is empty. Cached images are encrypted, bounded, reusable offline and removable in Settings. Unavailable icons keep the existing initial. Windows uses direct fixed-path HTTPS; PWA uses the included Pages endpoint. Enabling adds a random key in ordinary encrypted KDBX custom data; downloads do not change entries/history or backup revisions. Domain-only records with empty passwords now pass strict save/read-back verification. No vault format migration or separate icon-provider account is required. [Implementation and privacy](../FAVICONS.md).

Validation: 186 JavaScript unit tests, 13 production PWA browser scenarios, 71 isolated desktop UI scenarios plus two final layout/contrast checks, two native boundary/storage tests, all-target native Clippy with warnings denied, workspace typecheck, both builds and target isolation, and the compiled Pages endpoint check. Independent Python CLI recovery of a fresh icon-enabled domain-only KDBX exactly matched the complete browser model without changing the file. A public GitHub ICO was downloaded by CLI and normalized by the actual shared decoder in Chromium; this does not prove deployed Pages or native Windows network behavior.
