# PassKey Local 0.1.6 — canonical website icons

[Published release](https://github.com/kurasis/passkeylocal/releases/tag/desktop-v0.1.6) · [Windows x64 0.1.6 ZIP](https://github.com/kurasis/passkeylocal/releases/download/desktop-v0.1.6/PassKey-Local-Windows-x64-0.1.6-unsigned.zip). PWA 0.1.6 is deployed at [passkeylocal.top](https://passkeylocal.top).

Google's bare-domain favicon responds with a redirect to its `www` alias. The
PWA endpoint and Windows downloader previously rejected that hop and retained
the initial instead of the icon. Both now accept one exact HTTPS redirect to
the same fixed icon path on that domain's bare/`www` alias. No arbitrary hosts,
paths, query strings, credentials, ports or redirect chains are followed.
Windows resolves, validates and pins public DNS addresses for the alias too.

Previously cached missing icons are retried after upgrading; downloaded icons
stay cached and encrypted. A raster decode failure is retryable on the next
list visit, rather than being stored as a confirmed absence. ICO/PNG decoder
blobs now declare their actual image type.

For PWA, update the installed app while locked. For Windows, install the
separate **0.1.6** desktop distribution over the existing installation. Neither
path requires clearing website data or deleting the vault. Enable website
icons in Settings and return to the entry list. The Website field takes
priority; without it, the title must be a domain such as `google.com`.
Sites without a supported icon keep their initial.

Regression checks include a synthetic canonical redirect through endpoint,
browser ICO decoding and encrypted cache behavior; blocked targets and redirect
chains remain rejected. Hosted checks now request both Google and GitHub icons.
Publication and target-machine acceptance are recorded separately in
[release evidence](../RELEASE_EVIDENCE.md).
