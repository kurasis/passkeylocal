# PassKey Local 0.1.4 — reliable PWA update discovery

The locked browser screen now offers **Check for updates**, shows check/download
progress and failures, and offers **Update now** after a complete shell is ready.
Updates already installing when the observer attaches are detected; late
registration, replaced workers and observer cleanup are handled. Startup,
visible/focus/online returns and locking recheck with a one-minute automatic
throttle. Explicit checks bypass that throttle. SW script HTTP caching is bypassed.

Activation requires an explicit locked-screen action. The unlock form is inert
while applying; a failed activation times out instead of leaving it disabled.
No automatic reload during editing, IndexedDB cleanup, or vault format change
is introduced. Failed downloads keep the old complete offline shell usable.
Native Windows does not use this PWA updater.

## Recover an older cached interface

The fix cannot add controls to JavaScript already running from an older offline
shell. On desktop Chrome/Edge, use **Ctrl+Shift+R** once to request the current
page from the network. Apply the waiting update from the locked screen, or use
**Check for updates** in 0.1.4. Closing all tabs/windows/PWA instances for this
site and reopening also lets the browser finish a waiting worker's lifecycle.
Do not delete site data/IndexedDB or uninstall the PWA to force an update.

The native Windows application installed from an EXE has its own distribution;
publishing Cloudflare does not update that executable. This web change does not
publish a new Windows installer or claim physical-device/Safari acceptance.

The existing Cloudflare **Build command** stays `node package.mjs`; no further
hosting setting change is needed. Versioned Pages/Workers/static archives and
SHA-256 sidecars are in [deployment folders](../../deploy/cloudflare-workers/).
See [release evidence](../RELEASE_EVIDENCE.md) for executed checks and deployment
status.
