# PassKey Local 0.1.5 — update recovery with multiple tabs

Completes the [0.1.4 PWA updater](0.1.4.md) for a hard-reloaded page that has no
controller while another tab keeps an old active service worker alive. A waiting
update is offered in this case too; a first installation still is not presented
as an upgrade. Existing 0.1.4 archives remain unchanged.

The locked screen provides **Check for updates** and explicit **Update now**.
To leave an old cached interface, use Ctrl+Shift+R once in desktop Chrome/Edge,
or close all site/PWA windows and reopen. Confirm `PassKey Local (0.1.5)` in the
window title. No site-data deletion or Cloudflare settings change is needed.
On iPhone/iPad, lock the vault, leave the PWA online briefly, then fully close
it from the app switcher and close site tabs in Safari. Reopen from the Home
Screen; if a download is still finishing, repeat the close/reopen after it
finishes. Do not delete the installed PWA or clear Safari website data. These
are recovery instructions, not a claim of physical iOS acceptance. An installed
native EXE uses its separate distribution.

Validation includes the no-controller/active-registration unit case and a real
Chromium network-bypass reload in a second tab while an unsaved editor remains
open in the first. The recovery page sees the waiting update; the editor is not
reloaded. Explicit lock/apply preserves IndexedDB ciphertext, and a later failed
install still permits offline password unlock. Physical Safari/iPhone and
installed Windows acceptance are not claimed. See [release evidence](../RELEASE_EVIDENCE.md).
