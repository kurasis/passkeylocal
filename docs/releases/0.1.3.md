# PassKey Local 0.1.3 — PWA icon retry fix

The browser now retries icon downloads after a temporary endpoint failure when
the user returns to the list. WAF pages, missing endpoints, rate limits, server
errors and HTML fallback responses no longer become one-day negative-cache
entries. Confirmed missing/unsupported icons still retain initials and a bounded
negative cache. Legacy misses are rechecked once; existing valid icons remain.
Website priority, encrypted cache, consent, fixed HTTPS paths, image bounds and
vault/backup formats are unchanged.

- [Complete Workers package 0.1.3](../../deploy/cloudflare-workers/passkeylocal-cloudflare-workers-0.1.3.zip)
- [Static-only Workers package 0.1.3](../../deploy/cloudflare-workers/passkeylocal-cloudflare-workers-static-0.1.3.zip)
  cannot install the icon endpoint.

For an existing GitHub-connected Worker, change **Build command** once to
`node package.mjs` with root `deploy/cloudflare-workers`. The previous command
explicitly extracted 0.1.2 on every build. The new command selects the current
versioned Pages archive and verifies its checksum. Do not edit the Worker name,
hostname or deploy command. No local installation is needed.

Executed: 189 unit tests, workspace typecheck, 14 production PWA browser tests,
both frontend builds/isolation, version consistency, compiled endpoint checks,
legacy cache migration and failed-request retry regression. The new browser
regression first failed against 0.1.2. Real GitHub/Google/Yandex ICO files passed
the shared decoder in Chromium. This is local decoder evidence, not proof that
the owner's Cloudflare allows API requests. Current direct requests from the
development environment receive HTTP 403 on both shell and endpoint; live
availability must be recorded separately.

Package/native versions are synchronized. This change does not publish a new
Windows installer or claim native/physical-device acceptance. Existing published
0.1.2 assets remain unchanged. See [release evidence](../RELEASE_EVIDENCE.md).
